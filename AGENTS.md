# AGENTS.md — map of win98-site-kit for agents and humans

This repository is a starter kit plus CLI for Windows 98 style desktop
websites, extracted from [rohin.shanker.me](https://rohin.shanker.me/). There is
no build step: a site is plain HTML, CSS and ES modules served statically.

## Layout

| Path | What it is |
| --- | --- |
| `template/` | The starter site a user gets from `win98-site-kit init`. Everything a site needs lives here. |
| `template/index.html` | Shell page: an empty desktop, window stack and taskbar; `kit/boot.js` fills them. |
| `template/site.config.js` | The user-facing config: title, background, calendar, cursor, desktop/dock order. Validated by `kit/config.js`. |
| `template/kit/` | The core ES modules (window manager, desktop, dock, calendar, background, carousel, alerts, cursor, media, storage, util). `kit/index.js` is the public API. |
| `template/apps/<id>/index.js` | One app per folder; default-exports an app definition (contract in `kit/apps.js`). `apps/installed.js` is generated by `win98-site-kit sync`. |
| `template/styles/` | `98.css` (vendored, MIT), `kit.css` (layout and components), `cursors.css` (cursor tokens, inert until a pack is installed). |
| `template/assets/` | 626 Windows icons under `app-icons/ico/`, backgrounds, fonts, 98.css icons, Pixelarticons, placeholder photos, empty `cursors/` skeleton. |
| `registry/apps/<id>/`, `registry/games/<id>/` | Downloadable packages. Each has `manifest.json` and a tree mirroring the site root (`apps/<id>/…`, `assets/<id>/…`). |
| `cli/`, `bin/` | The `win98-site-kit` command: `init`, `add`, `remove`, `list`, `sync`, `serve`. |
| `showcase/` | Generated demo site: the template plus every registry package. Rebuild with `npm run showcase:build`; `npm run showcase:check` fails when it is stale. |
| `scripts/` | Repo tooling (`build-showcase.mjs`, `syntax-check.mjs`). |
| `tests/` | Node tests (`*.test.mjs`) and Playwright UI tests (`tests/ui/*.spec.mjs`, run against `showcase/`). |
| `docs/` | Validation runbooks (`docs/validation/`) and live tickets (`docs/notes/tickets/`). |

## Commands

```bash
npm test                 # node --test tests/*.test.mjs
npm run test:ui          # Playwright against showcase/ (needs npx playwright install chromium once)
npm run showcase:build   # regenerate showcase/ from template + registry
npm run check            # syntax + showcase freshness + node tests
node bin/win98-site-kit.mjs serve template --port 4310   # serve any site directory
```

## How a site boots

1. `index.html` loads `kit/boot.js` as a module.
2. `boot.js` normalizes `site.config.js` (`kit/config.js`) and the app list from `apps/installed.js` (`kit/apps.js`).
3. It applies the background and cursor mode, injects each app's `styles`, then creates a hidden `.window` element per app (`kit/windows.js createWindow`) and calls the app's `mount()`.
4. It renders desktop icons and the taskbar from the `desktop` / `dock` placement lists, starts the clock and the calendar, and binds every `[data-app]` launcher.
5. `index.html#<app-id>` opens that window on arrival. `window.win98SiteKit` exposes the API for debugging.

## The app contract (see `template/kit/apps.js` for the full comment)

```js
export default {
  id: "my-app",                                  // kebab-case, unique
  title: "My App",                               // title bar and icon label
  icon: "assets/app-icons/ico/notepad.ico",
  styles: ["apps/my-app/my-app.css"],            // optional
  window: { width: 420, controls: ["minimize", "maximize", "close"], center: false, resizable: false, dialog: false },
  render: () => `<p>Hello</p>`,                  // window-body HTML (string, Node or fragment)
  mount({ window, body, kit, app, config }) {},  // once, after the element exists
  onOpen(win) {}, onClose(win) {}, onResize(win) {}, onKeydown(event, win) {},
  windows: [{ id: "my-app-rules", title: "Rules", window: {...}, render: () => "…" }],  // extra windows
};
```

A link app is `{ id, title, icon, href }` and opens a new tab.

Kit API highlights (`import { … } from "../../kit/index.js"`):

- Windows: `openWindow(id)`, `closeWindow(id)`, `toggleWindow(id)`, `getWindow(id)`, `isWindowOpen(id)`, `bringToFront(el)`, `clampIntoViewport(el)`, `registerKeyHandler(id, fn)`, `onViewportResize(fn)`, `onWindowOpen(fn)`, `onWindowChange(fn)`, `closeAllWindows()`, `onCloseAll(fn)`.
- Dialogs: `showAlert({ title, icon, body, buttons })` → resolves with the pressed button id.
- Content: `createCarousel(container, items, { variant })`, `selectorWindowBody(items)` + `mountSelectorWindow(win)`, `loadDeferredMedia(root)`, `setLoading(slot, bool)`.
- State: `storage.readJson / writeJson / remove`, `createProgressLoader`, `flashBanner`, `clamp`, `pad2`, `prefersReducedMotion`, `escapeHtml`.
- Settings: `setBackground`, `backgroundChoices`, `setCursorMode`, `observeLoading(predicate)`.

Media inside windows may use `data-src` instead of `src`; the kit loads it when the window first opens. Mark `<video data-unload-on-hide>` to release it on close.

## Styling rules

- Reuse 98.css classes (`window`, `title-bar`, `window-body`, `field-row`, `sunken-panel`, `status-bar`, `tabs`, `tree-view`) and the tokens in `kit.css` (`--frame-padding: 6px`, `--frame-inset: 2px`, `--window-gap: 12px`, `--controls-gap: 8px`).
- Carousel spacing contract: sunken frame with 6px padding, media slot with 2px inset on a white (image) or black (video) field, controls 8px below, frame 12px below preceding text. Variants set the slot height: `image` 180–340px, `video` 220–440px, `pdf` 220–480px, `poster` 220–460px, `photo` fixed aspect ratio (`--gallery-aspect`).
- Windows must work at 375×812, 768×1024, 1280×800 and 1440×900. Use `min(…, calc(100vw - 24px))` widths and `max-height` with internal scrolling; never rely on the page scrolling.
- Icons: pick from `assets/app-icons/ico/` (browse `showcase/index.html#icon-browser`). Use `image-rendering: pixelated` only for intentionally tiny pixel art.

## Adding a registry package

1. Create `registry/<apps|games>/<id>/manifest.json`:

   ```json
   {
     "id": "snake",
     "kind": "game",
     "title": "Snake",
     "description": "Classic snake with local high scores.",
     "version": "1.0.0",
     "files": ["apps/snake/index.js", "apps/snake/snake.css", "assets/snake/logo.png"],
     "requires": []
   }
   ```

2. Put the files at exactly those paths inside the package folder. `files` must list every file in the folder except `manifest.json` (a test enforces this) and must include `apps/<id>/index.js`.
3. Keep per-package assets under `assets/<id>/` so `remove` can clean up.
4. Add a node test under `tests/packages/<id>.test.mjs` for pure logic and a Playwright spec under `tests/ui/<id>.spec.mjs` that opens the window in the showcase at the four viewports.
5. Run `npm run showcase:build`, then `npm run check` and `npm run test:ui`.

Packages must not touch `kit/` files. If the kit lacks something, add it to `template/kit/` in a separate commit with a test.

## Conventions

- Two-space indent, double quotes, semicolons, ES modules, no bundler, no framework.
- Every module starts with a short comment saying what it owns. No TODOs or stubs.
- Tests ship with the code. UI work is verified by rendering the real page, not by reading source.
- Tickets live in `docs/notes/tickets/` (`O_`/`A_`/`R_` prefixes, see `docs/validation/context-system.md`); reusable runbooks live in `docs/validation/` and are indexed in `docs/validation/INDEX.md`.
- The kit ships no backend. The one server-side piece is the optional Clash Royale proxy that the `clash-royale` package installs under `proxy/clash-royale/`, documented in its README.
